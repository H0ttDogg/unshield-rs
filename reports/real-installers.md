All valid ASUS descriptors have compressed-only flags `0x0004`, volume 1, and no link
flags. Each complete ASUS input set includes `data1.cab`, `data1.hdr`, and an empty
512-byte `data2.cab`. Two numbered CAB files do not establish split-file coverage.

JBeijing7's 11 valid members with the previous-file bit set are indices 123,
127, 128, 129, 132, 133, 135, 136, 138, 139, and 140. Examples include chains
`138 -> 135 -> 132 -> 130` and `139 -> 136 -> 133 -> 131`.

including both ends of those chains. The raw descriptor layout uses 0x57-byte
records and link fields at offsets 0x4c, 0x50, and 0x54. Rust assertions verify
those raw fields, while C-generated hashes independently verify every output.

## Unicode-name follow-up (T3-02)

Sony SFCard Viewer 2.6.4 contains a real format-26 file-group record named
`ｱﾌﾟﾘｹｰｼｮﾝ実行可能ﾌｧｲﾙ`. This is group index 8 in the original C metadata,
with first/last member indices 26 and 32. Six of those seven records are valid:
26, 27, 28, 29, 30, and 32. Record 31 is invalid and contributes no name evidence.
The valid members include the application executable, libraries, help, settings,
and a license file. Every basename and directory name is ASCII. The non-ASCII
scope is precisely the file-group name, not Unicode file basenames.

The original header stores this name in UTF-16LE; both C and Rust return the
same UTF-8 bytes. The inventory's `name_evidence` records the group and its six
valid member references. The inventory contract test checks this against the
independent expected JSON even when installer downloads are absent. Normal
corpus tests compare every directory, component, group, and valid file record,
plus every valid member's expanded size and SHA-256.

All 20 valid descriptors have compressed-only flags 0x0004 and no link flags;
14 belong to volume 1 and six to volume 2. No member crosses volumes. The raw
version word is 0x04000a28, independently identified as major 26 by the upstream
high-byte-4, low-16-bits / 100 rule.

The archived official Sony installer has SHA-256
`bb17f07066cf0dfa6ea4dedfce32c8db79a0c1c5e3a118584da44de194472c9b`.
Its original live URL now redirects to a web page, so the inventory pins the
2021-11-27 archived original response. It is prepared without executing the
installer, using its verbatim byte ranges and the UTF-16LE launcher headers:

| Input | Installer offset | Bytes |
| --- | ---: | ---: |
| data1.cab | 965,900 | 862,110 |
| data1.hdr | 1,828,090 | 14,360 |
| data2.cab | 1,842,534 | 2,225,285 |

With all four packages required, Linux passed all 35 Rust integration tests,
five Python tooling tests, independent C reproduction, shared/static CTest
suites, installed native/callback consumers, and Sony CLI list/test/extraction.
Formatting, Clippy with warnings denied, and diff whitespace checks also passed.
See [the retained local output](2026-10-19-unicode-groups.log).

## Split-volume follow-up (T2-03)

The [original Epson TWAIN driver download](https://ftp.epson.com/drivers/epson10609.exe)
is listed as TWAIN Driver 5.71A (Rev.F), dated 2002-12-10, on
[Epson's Perfection support page](https://epson.com/Support/Scanners/Perfection-Series/Epson-Perfection-1260/s/SPT_B11B154011?review-filter=Windows+98).
Its self-extracting ZIP is 6,408,480 bytes with SHA-256
`40fff4d212cd00d15a5b46d321b335d6e567e1f9842e42c88005c0da882d1723`.
Preparation uses the existing ZIP reader to select `DATA1.HDR` and all six
`DATA1.CAB` through `DATA6.CAB` members; the executable is never run. The inventory
pins all seven selected members separately. The raw version word 0x0100600c
identifies InstallShield format 6 under the pinned upstream major-version rule.

Four physical members carry flags 0x0005 (`FILE_SPLIT | FILE_COMPRESSED`):

| Member index | Name | First segment: volume, offset, stored bytes | Continuation: volume, offset, stored bytes | Complete compressed bytes |
| ---: | --- | --- | --- | ---: |
| 30 | ESTW5.ds | 2, 348827, 14693 | 3, 512, 89214 | 103907 |
| 47 | PER124_R.ICM | 3, 1336221, 121443 | 4, 512, 63953 | 185396 |
| 55 | PER165_R.ICM | 4, 1349161, 108503 | 5, 512, 75930 | 184433 |
| 63 | PER610_R.ICM | 5, 1358526, 99138 | 6, 512, 85395 | 184533 |

Each first segment is the last member of its cabinet, and its continuation is
the first member of the next cabinet. Both segments have positive lengths, lie
within their respective files, and sum to the descriptor's complete compressed
size. The first member expands to 262,144 bytes, the next two to 197,564 bytes
each, and the last to 197,556 bytes. Linked records 151 and 175 reuse member 30's
payload through the chain `175 -> 151 -> 30`; they do not add physical splits.

The Rust corpus harness checks the pinned boundaries against the original volume
headers. A storage probe observes each physical member opening exactly its two
declared volumes. Denying its continuation through that probe must fail extraction;
no downloaded file is renamed or modified for this negative check. Full metadata,
expanded sizes, and SHA-256 hashes for all 170 valid members match the separately
built original C implementation, including all linked records. The independent
expected JSON is [retained with the corpus](../corpus/expected/epson-twain-571a.json).

Local validation passed the full Rust suite, the focused corpus tests with the
volume probe, formatting, Clippy, independent C reproduction for all five samples,
shared/static CTest suites (five checks each), installed native/callback CTest
(two checks), and Epson CLI list/test/extraction. A separate fresh download
through the exact corpus fetcher also passed every input hash. See
[the retained local output](2026-10-19-split-volumes.log).
The workflow requires all five samples on Ubuntu, Windows, and macOS; execution
of that extension is pending.

## Limits and next samples

This closes the first milestone of one authentic sample per newer-format family.
It does not establish support for every version between 6 and 26. JBeijing7
adds another producer, actual application/dictionary payloads, narrow non-ASCII
names, and genuine links. It closes T2-02 and the linked-member option of T3-03.
T3-02 is completed by the Sony format-26 UTF-16LE file-group record described
above. Non-ASCII UTF-16LE file basenames and directory names remain additional coverage
gaps. Epson format 6 closes T2-03 with four physical members crossing cabinet volumes.
No real obfuscated-member coverage is claimed.

Earlier archive-only candidate inspection ruled out these inputs:

| --- | --- | --- |
| ChineseWriter11 1.08 | [Vendor update](https://www.kodensha.jp/sstec/update/cw/cw11up.exe) | Embedded CAB/HDR raw version 0x02000640 is format 16. |

| Samsung Kies3 3.2.16084_2 | [Vendor archive](https://downloadcenter.samsung.com/content/SW/201611/20161118155850485/Kies3Setup.exe) | Launcher contains an MSI payload; no InstallShield CAB set was identified. |
| HP sp72968 | [Upstream issue attachment](https://github.com/twogood/unshield/files/116199/sp72968.zip) | Format 21, but every valid member filename is ASCII. |

These candidates were not promoted or counted as passing corpus samples.
No installer was executed. The later Sony sample provides genuine Unicode
name evidence in a referenced file-group record, with complete volumes and
independent expected extraction.

Generated tests cover several features absent from these real packages. Those
tests remain separate evidence. The older 610 hashes represent extracted files
from four datasets, not 610 installers; combined content checks cover 1,059 files
across nine datasets/packages.

Rust CLI listing/testing passed on all three systems, and extraction passed on
Ubuntu. Windows extraction of
their `<Support>` group paths is rejected by its filename policy. The portable
library/C comparisons use member-index output filenames and cover every valid
member, including duplicate names. Exact original CLI behavior remains a
separate compatibility claim.

Human cross-review remains pending. Three custom-callback tests previously
[passed under Miri](miri/2026-10-17-callbacks.md), but this is not a full-suite
Miri pass. The C boundary still requires unsafe pointer/callback operations;
the parser/extractor/CLI forbid unsafe Rust. Differential fuzzing remains deferred.
