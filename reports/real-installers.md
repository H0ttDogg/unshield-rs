# Real installer validation

Snapshot: 2026-10-19. Production Rust code is unchanged from `dd26dcb`; the
current integration adds corpus inputs, C consumers, CI checks, and documentation.

## Measured sample coverage

| Package | Format | Total records | Valid members checked | Expanded bytes checked |
| --- | ---: | ---: | ---: | ---: |
| [ASUS SoundMAX ADI1988A 5.10.01.4570](../corpus/v6-16.json) | 9 | 328 | 54 | 6,958,560 |
| [ASUS Realtek LAN 10.5.511.2021](../corpus/v17-plus.json) | 21 | 153 | 75 | 49,752,365 |
| **Total: two packages** | | **481** | **129** | **56,710,925** |

Every valid member is compared against metadata and SHA-256 hashes generated by
the original C library at `cbed3d19ef9cdf4e5fb86b9d65e48f1bf8d539db`.
The independent reference was rebuilt and run on Linux x86_64 (WSL) on this date.
All 54 format-9 expectations were recorded from that executable; all 75 existing
format-21 expectations reproduced. Neither expectation set comes from Rust.

The 352 invalid records are counted and checked for validity, but not extracted.
Their placeholder names have no compatibility significance. CAB contents are
installer support resources; driver payloads and Microsoft CAB files elsewhere
in the downloaded ZIPs are outside this comparison. The installers were never run.

| Feature | Format 9 | Format 21 |

| Compressed members | Present: all 54 | Present: all 75 |
| UTF-16LE name storage | Absent | Present |
| Non-ASCII names | Absent | Absent |
| Members split across volumes | Absent | Absent |
| Obfuscated members | Absent | Absent |
| Linked members | Absent | Absent |
| External CAB payload files | Absent | Absent |

All valid descriptors have compressed-only flags `0x0004`, volume 1, and no link
flags. Each complete input set includes `data1.cab`, `data1.hdr`, and an empty
512-byte `data2.cab`. Two numbered CAB files do not establish split-file coverage.

## Execution evidence

Local Windows x64/MSVC validation on 2026-10-19 passed:

- All 34 Rust integration tests, including the existing four upstream datasets
  with **610** expected extracted-file hashes and the traversal rejection test.
- Both newer real packages: all 129 valid members' metadata, sizes, and hashes.
- Three Python corpus-tool tests, including nested ZIP preparation, corruption
  rejection, and preventing the C replacement from recording expected results.
- CMake shared and static builds: five CTest checks each, including native and
  custom-callback extraction of both real packages.
- Installed shared-library consumer: both real-input modes plus the existing
  all-public-functions C ABI test. Callback resources closed in balance.
- `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings`.

An initial sandboxed Rust run denied filesystem operations in two existing CLI
tests. Rerunning the full suite with normal filesystem access passed; no source
fix was required. No production parser/extractor mismatch was found in these
real inputs.

The preceding [CI run at dd26dcb](https://github.com/H0ttDogg/unshield-rs/actions/runs/39097002038)
passed on Ubuntu, Windows, and macOS for the format-21 Rust comparison. The new
workflow requires both samples and the C checks on all three systems, rebuilds
the independent C oracle on Ubuntu, and tests the relocated static pkg-config
consumer there. The new integration's cross-platform run is pending publication.

Run commands and artifact locations are documented in
[corpus/README.md](../corpus/README.md). CI preserves comparison logs and CTest
logs as workflow artifacts; binaries and temporary extraction output are ignored.

## Limits and next samples

This closes the first milestone of one authentic sample per newer-format family.
It does not establish support for every version between 6 and 21. Both packages
come from ASUS and predominantly contain installer engine/support resources.
Prioritize independent producers, CAB-contained application/driver payloads,
non-ASCII names, and genuinely split/obfuscated/linked members next.

Generated tests cover several features absent from these real packages. Those
tests remain separate evidence. The older 610 hashes represent extracted files
from four datasets, not 610 installers; combined content checks cover 739 files
across six datasets/packages.

Rust CLI listing/testing can exercise these archives, but Windows extraction of
their `<Support>` group paths is rejected by its filename policy. The portable
library/C comparisons use member-index output filenames and cover every valid
member, including duplicate names. Exact original CLI behavior remains a
separate compatibility claim.

Human cross-review remains pending. Three custom-callback tests previously
[passed under Miri](miri/2026-10-17-callbacks.md), but this is not a full-suite
Miri pass. The C boundary still requires unsafe pointer/callback operations;
the parser/extractor/CLI forbid unsafe Rust. Differential fuzzing remains deferred.
